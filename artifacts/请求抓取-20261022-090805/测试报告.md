日期：2026-10-22（Asia/Shanghai）。结论：本次 Strata 普通新会话的两种模式符合请求语义。

## 方法

复制当前 Desktop Profile 的 package.json、cordis.yml、cordis.patch.yml，复用同一 node_modules 和插件源码，启动独立 Web 实例；DSH_HOME、会话与插件状态隔离。未重启或修改正在运行的 Desktop。安装目录的 llm-pi-ai 版本为 0.2.1-rc.2。

临时诊断插件通过 sessionController 创建两个 standard 会话，经原插件 /dsh-spm/mode 接口选择 native / none。在 globalThis.fetch 边界记录适配器序列化后的 UTF-8 原始请求体，然后原参数调用原 fetch。没有保存 Authorization 或 Cookie。

固定输入：`请只回复：WIRE_TEST_OK。不要调用工具。`

模型与参数：Strata / qwen3.8-flash-next-iq3_s / medium / maxTokens 12288。目标为 https://130.130.130.229/v1/chat/completions。保留 TLS 校验，使用本地 Strata CA。

## 标题请求与验收边界

native-2.request.json 与 none-2.request.json 是独立会话标题请求：两者完全相同，均有自己的 developer 标题指令、无工具、HTTP 200。插件没有清除标题服务的独立提示词，不能宣称整个应用所有请求均无提示词。

本次为当前 Profile 的隔离运行测试，不是正在运行的 Desktop 进程 GUI 验收。对比此前 Desktop 会话，本实例缺少宿主注入的 load_workspace_dependencies 工具，技能目录按本实例实际发现结果生成。本次两轮之间的上下文和工具完全相同。

只覆盖全新普通会话，不覆盖自定义、历史切换、子 Agent、/goal 或其他 Provider。抓取证明客户端交给 HTTP fetch 的内容及服务端 HTTP 200/实际生成结果，不观察服务端内部模板或注入。
