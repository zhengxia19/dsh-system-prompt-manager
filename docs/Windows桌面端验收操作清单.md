# Windows DSH Desktop 实机验收操作清单

目标：DSH Desktop `0.2.1-rc.2`、已配置的 Strata/OpenAI 兼容模型。只有真实桌面请求可以关闭 A03、A09、A10、A14 的验收空缺。CI 和 Mock 结果不得代替实机结果。

## 安装

1. 检查桌面版实际版本。若不是 `0.2.1-rc.2`，先记录版本，不把其他版本结果当作目标版兼容证据。
2. Plugins → 添加第三方插件，输入 `https://github.com/zhengxia19/dsh-system-prompt-manager.git`，启用。
3. 打开新会话，确认输入框左侧显示“系统提示词 · 原生”。如加载失败，保留 DSH 插件日志（删除 API Key）。
4. 在面板新建模板，文本使用易辨识的英文或中文短串，并保留前后空格、换行及字面 `{{literal}}` 进行原文保真测试。
5. 在两个并行会话分别选择“原生”与“自定义”，在第三个会话选择“无系统提示词”。

## 请求验证（必须采集真实出站消息结构）

在经用户授权的测试 Provider 端或本地调试代理进行采样，不要求上传 API Key。每次发送固定用户消息，分别核对：

- 原生：模型调用中的系统内容与未安装插件基线相同。
- 自定义：整个系统提示词恰为模板完整文本，不能出现 DSH 原生段或额外插件强制规则。
- 无提示词：Provider 发送的 JSON 中既无顶级 `system`，也无 `messages[].role == "system"`。**一个内容为空的 system 项不能算通过。**
- 工具 Schema 与会话用户消息保持正常；注意存在请求转码与模型服务端模板，不要将服务端行为误记成客户端消息。

如果 Provider 通过 pi-ai 适配器将开头内部空 system 占位过滤，应在报告中分别记载“内部事件”与“外发 JSON”；若仍外发非空 system 则本模式失败，停止发布。

## 状态与子 Agent

1. 普通会话测试模板更换：下一轮生效，历史影响提示可见，不删除历史。
2. 运行中切换为另一模式：当前任务维持原模式，完成后下一轮切换生效。
3. 主 Agent 触发子 Agent 任务；在子任务运行时切换或编辑模板；子 Agent 必须保留主任务启动时冻结的原始文本。重复多级子 Agent。
4. 用 `/goal` 模式运行最小无副作用任务，确认状态结束、工具不受损、子 Agent 模式继承正确。
5. 关闭再启动桌面客户端，恢复每个会话的模式和模板；删除被引用模板应得到明确拒绝。

## 冲突和故障

安装另一个有生效 `complete` section 的测试插件，须给出冲突错误，不允许拼接或静默回退。再模拟不可写存储、损坏 state.json，确认没有覆盖用户已有数据或伪造成功状态。
