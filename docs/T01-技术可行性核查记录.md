# T01 技术可行性核查记录（阶段性阻断）

核查日期：2026-10-20
目标基线：官方 `deepseek-ai/deepseek-harness`，标签 `dsh-v0.2.1-rc.2`（对应发布版 v0.2.1-rc.2）。
状态：**发现 P0 技术阻断，T01 未验收通过；T02–T10 未开始。**

## 已确认的源码事实

1. `packages/core/system-prompt/src/index.ts` 暴露 `PromptSection.complete?: boolean`。一个 complete 段可覆盖全部系统提示词段；多段 complete 会抛出异常。此机制不能单独保证模型请求中完全不存在 system 消息。
2. `packages/core/agent-loop/src/agent.ts` 的 `step()` 调用 `renderPrompt(assembly)`，然后将 `SystemPromptProjection.project()` 的结果作为 `system/message` 追加到 Session。
3. `packages/core/agent-loop/src/runtime-context.ts` 中 `SystemPromptProjection.project()`：当还不存在头部 system 节点时，无条件返回 `createSystemMessage(rendered)`，**即使 rendered 是空字符串**；注释也注明初始空提示词会占据 surface node 0。
4. 同版本 `agent.ts` 在请求构造时以 `session.deriveMessages()` 生成 `messages`，并冻结后交给模型调用；不能凭 systemPrompt 段置空断言请求无 system 项。
5. 官方 LLM API 类型 `GenerateOptions.messages` 定义为供适配器接收的完整消息列表。对 system 项进行额外删除必须考察请求转换/适配器，不能通过 `PromptSection.complete` 推导成功。

## P0 阻断判断

本项目 F03/A03 要求实际发送给模型的请求**不存在任何 `role=system` 项**，而非空字符串。当前已检查的公开 `ctx.systemPrompt` 功能不足以实现该验收；官方 Agent Loop 则会为渲染结果创建空 system 节点。

尚未完成完整 Provider 适配器序列化审计，也没有证据证明公开插件 API 存在一个可以安全删除请求 system 消息、并保持会话日志可重放的可靠扩展点。因此不能声称纯插件实现已确认可行。

根据实施任务清单 T01 的硬门槛，**不得擅自修改 DSH 核心源码、不得降级无提示词语义，也不得跳过 T01 直接启动后续依赖任务**。

## 需决定的技术路线

- A. 保持“实际请求无 system 消息”验收语义：允许为 DSH 官方上游提出一个最小扩展接口/补丁（优先 PR），待接口可用后继续插件开发；不直接篡改本机已安装 DSH。
- B. 保持“仅公开插件 API、不修改上游”：继续调查 Provider 适配器或合法插件扩展点。若无法去除 system 项，应明确 V1.0 无法完整验收，不能以空 system 消息替代。
