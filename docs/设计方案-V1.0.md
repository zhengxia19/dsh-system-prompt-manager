# 设计方案 V1.0（已确认）

## 1. 项目边界

构建独立 DSH Desktop 插件，提供系统提示词模式和模板选择，兼容目标 DSH Desktop `0.2.1-rc.2`。V1 不实现 AI 生成提示词、自动优化、云同步、模板市场、模型参数或 Control Vector 管理；不修改 DSH 核心。

## 2. 三模式准确语义

| 模式 | 系统角色消息要求 | 其他消息与能力 |
|---|---|---|
| 原生 | 与未启用插件时的 DSH 请求一致 | 不主动改变 |
| 自定义 | 仅包含选定模板的系统文本，不附加原生段 | 用户、工具、正常运行时上下文保留 |
| 无提示词 | 最终传入模型适配器的消息列表无 `system` 角色消息 | 用户、工具消息保留，不伪装为删除全部上下文 |

验证对象必须是**最终实际传给模型 Provider 的请求**，同时对比内部组装结果。`system` 字符串为空与消息不存在不是同义词。系统提示词之外的客户端附加消息、模型服务端模板可能继续发挥作用，插件对此不得作超范围承诺。

## 3. UI

- DSH 输入框常驻“原生／自定义／无提示词”选择器。
- 选中自定义时出现模板选择器及进入编辑的入口；状态清楚可见。
- 插件设置管理模板：新增、编辑、复制、重命名、删除、导入、导出。
- 纯文本模板，不隐式展开 `{{...}}`，不额外加入人格、安全或工具交互规则。
- 预发送时检查当前会话模板有效性；如有错误，阻止任务发送并给出明确处理建议。

## 4. 状态模型

- 默认新会话为原生；用户可调整默认模式。
- 每个会话保存 `mode`、`templateId`、`templateRevision` 和必要状态。
- 发送时冻结 `executionSnapshot`：模式、模板标识、精确文本、版本、创建时间（用于诊断），任务及其子 Agent 使用同一快照。
- 主 Agent 创建子 Agent 时，继承快照；运行期间切换不会追改已发请求或已创建的子 Agent。
- 会话中途可切换，下一轮请求生效；提示之前历史仍可能影响模型，不删除历史。
- 编辑模板后，后续**新请求**读取最新版本；已开始任务保持原快照。
- 删除仍被引用的模板后，会话进入“待重新选择”，不自动用另一自定义模板替代。
- 重启后恢复会话选项；运行时快照的存活、回收及持久化界限以验证结果确定。

## 5. 失败与冲突处理

- 原生模式不得污染原有 DSH 请求。
- 自定义模式如遇另一个 `complete` 段冲突，必须报告冲突，不得抢占或直接拼接。
- “无提示词”若公开插件接口不支持彻底移除，明确标记未实现，禁止以空文本变通。
- 模板丢失、文本无效、存储失败、作用域失配等错误在发送前提示，禁止静默回退。
- 禁用/卸载插件后由 DSH 恢复原生行为；不修改 DSH 核心持久配置。

## 6. /goal 与子 Agent

覆盖普通模式、`/goal`、子 Agent 和多级子 Agent。默认继承执行快照，不改变 Agent 工具权限。需要验证系统提示词注册作用域与子 Agent 生命周期，并避免父子任务对话状态串扰。

## 7. 非功能要求

- 本地状态持久化；不上传模板；日志不记录完整敏感提示词（除用户主动诊断导出时）。
- 独立插件，允许卸载；避免依赖未公开 DSH 内部实现。
- Windows Desktop 为首要验收平台，编译和单元测试不能替代实际端到端测试。
- UI 默认中文，按 DSH 现有交互规范集成。
