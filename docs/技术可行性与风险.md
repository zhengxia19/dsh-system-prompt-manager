# 技术可行性与风险（待验证）

## 当前判断与证据等级

1. 原生模式：理论上可在插件不介入时恢复，仍须验证插件加载本身无副作用。
2. 完整替换：据前期公开资料，`ctx.systemPrompt` 注册段的 `complete: true` 是候选实现方案；需核对 DSH Desktop 目标提交版本和生效作用域。
3. 完全无系统提示词：**未确认**可纯公开插件 API 实现；必须追踪请求组装和 Provider 适配器。此为 T01 阶段阻断项。
4. 子 Agent 继承和 `/goal`：产品行为已确认，底层 API 及生命周期传播尚待测试。
5. 输入框控件：参考社区 dsh-plugin-masterprompt 的交互模式；并不证明在目标 Windows Desktop 已经兼容。

## 风险表

| 风险 | 级别 | 应对 |
|---|---|---|
| system 消息无法通过公开插件 API 删除 | 高 | T01 验证，失败则停止相关任务并提议上游扩展 |
| 多个 `complete` 段冲突 | 高 | 检测并拒绝发送，不覆盖其他插件 |
| DSH 作用域 API 不支持会话隔离 | 高 | 最小验证，禁止使用全局变量假装隔离 |
| Goal / 子 Agent 独立创建提示词 | 高 | 跟踪生命周期，快照继承测试 |
| 私有 UI 注入点升级变动 | 中 | 优先官方扩展点、限制版本与回归测试 |
| 历史消息保留旧规则影响 | 中 | 明确提示、建议新会话获得干净上下文 |
| 模板中的凭据被日志或诊断泄露 | 中 | 默认仅摘要/哈希，显式导出时提醒 |
